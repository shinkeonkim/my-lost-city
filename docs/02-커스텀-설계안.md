# 커스텀 온라인 버전 설계안 (초안)

> 원칙: 게임 **메커니즘**(열 쌓기·와거·버림 더미·점수식)은 차용하되, **이름·일러스트·보드 외형은
> 자체 제작**한다. 원작 제목/아트/로고를 쓰지 않는다. 가제: "Expedition Lines"(변경 가능).

## 1. 요구사항 → 해결 방법

| # | 요구 | 설계 |
|---|---|---|
| 1 | QR/URL로 바로 입장 | 방 생성 시 `https://<도메인>/r/K7QX` 같은 짧은 코드 URL + 화면에 QR. 링크를 열면 닉네임만 입력하고 입장 |
| 2 | 방 암호 | 선택 사항. 서버에 해시로 저장. QR에 암호를 포함할지 토글(`#pw=...` 프래그먼트 → 서버 로그에 안 남음) |
| 3 | 색 2~6개 | 로비 설정 `colors: 2..6`. 색별 버림 더미/열이 동적으로 생성 |
| 4 | 기타 커스텀 | 아래 3장 |
| 5 | 3~4인 | 아래 2장 |

## 2. 3~4인 규칙 설계

구조는 그대로: **각자 자기 탐험대 열**, **색별 버림 더미는 모두가 공용**, 시계방향 턴.
문제는 카드 수. 손패 8장 기준, 플레이어당 뽑기 횟수(= 대략 턴 수):

| 인원 | 5색 2~10 (60장) | 6색 2~10 (72장) | 6색 2~12 (84장) | 5색 ×2벌 (120장) |
|---|---|---|---|---|
| 2인 | **22** (원작) | 28 | 34 | 52 |
| 3인 | 12 | 16 | 20 | 32 |
| 4인 | 7 | 10 | 13 | **22** |

원작 감각(약 20턴 내외)을 유지하려면 덱을 늘려야 한다. 두 가지 확장 장치를 제공하고
로비에서 **"예상 턴 수"를 실시간 표시**해 균형을 눈으로 맞추게 한다.

1. **숫자 범위 확장** (예: 2~12). 합이 커지므로 탐험대 비용을 자동 보정
   `비용 = round(20 × 숫자합 / 54)` (2~12 → 29). 수동 지정도 가능.
2. **덱 배수(같은 카드 2벌)**. 같은 숫자가 생기므로 이 모드에선 "같은 수 이상(≥)"을 허용.

권장 프리셋: 2인 = 원작(5색), 3인 = 6색 2~12, 4인 = 5색 ×2벌.
추가 선택지: **4인 팀전(2:2)** — 팀원 점수 합산, 팀원 열은 서로 보이지만 손패는 비공개.

## 3. 커스텀 옵션 목록

| 옵션 | 기본값 | 범위 |
|---|---|---|
| 색 수 | 5 | 2~6 |
| 숫자 범위 | 2~10 | 최소 1~, 최대 ~15 |
| 색당 와거 장수 | 3 | 0~5 |
| 덱 배수 | 1 | 1~3 |
| 손패 | 8 | 5~10 |
| 탐험대 비용 | 20 (자동 보정) | 0~60 |
| 장수 보너스 | 8장 이상 +20, 배수 미적용 | 장수/점수/배수적용 토글 |
| 같은 숫자 허용 | 끔 (덱 배수>1이면 자동 켬) | on/off |
| 방금 버린 카드 재획득 금지 | 켬 | on/off |
| 판 수 | 3 | 1~5 |
| 턴 제한시간 | 없음 | 30/60/120초, 초과 시 자동 버리기 |
| 남은 덱 장수 공개 | 켬 | on/off |
| 점수 미리보기(내 열 현재 점수) | 켬 | on/off (하드모드 끔) |
| 팀전 | 끔 | 4인일 때만 |
| 관전자 허용 | 켬 | on/off |

설정은 프리셋(원작 / 원작 6색 롱게임 / 3인 권장 / 4인 권장 / 빠른 게임)으로 저장·공유.

## 4. 아키텍처

```
[휴대폰/PC 브라우저]  ←WebSocket→  [Node 서버 (권위 서버)]
   React + Vite (모바일 우선)         · 방/로비/게임 상태(메모리)
   QR 생성, 재접속 토큰 저장          · 순수 게임 엔진(shared, 단위테스트)
                                      · 손패는 본인에게만 전송(치트 방지)
```

- 서버가 꼭 필요한가? → **필요.** 기기 간 실시간 동기화·숨김 정보(손패)·방 암호 검증 때문에
  최소한 시그널링/중계 서버가 있어야 하며, 그럴 바엔 서버가 판정까지 하는 게 단순하고 안전하다.
- 기술: TypeScript 모노레포 `packages/engine`(순수 로직), `apps/server`(Node + Socket.IO),
  `apps/web`(React + Vite). 컨테이너 1개로 정적 파일까지 서빙.
- 방 상태는 메모리 보관(재시작 시 진행 중 게임 소실 — 초기엔 허용, 필요 시 Redis).
- 재접속: 입장 시 받은 토큰을 localStorage에 보관 → 새로고침/화면 꺼짐 후 자동 복귀.

## 5. 배포 (oh-my-homelab)

`docs/service-dev-guide/` 흐름 그대로:
1. 이 레포에 Dockerfile + GitHub Actions → ghcr.io 이미지 push
2. oh-my-homelab에 `helm-charts/apps/<name>.yaml` + 매니페스트 **PR** (main 직접 push 금지, 사람이 merge)
3. 친구들이 외부에서 접속해야 하므로 **Cloudflare Tunnel Public Hostname**으로 공개
   (예: `cities.shinkeonkim.com`) — Zero Trust 대시보드 수동 작업 1회. WebSocket은 Tunnel에서 지원됨.
4. 시크릿은 현재 없음(방 암호는 런타임 데이터).

## 6. 진행 순서 제안

1. 엔진 + 단위테스트(공식 점수 예시 18점 재현 등)
2. 서버(방·암호·재접속) + 웹 UI(로비, QR, 게임 화면) → 로컬에서 휴대폰 2대로 테스트
3. 3~4인/팀전/옵션
4. Docker/CI → 홈랩 PR
