# 자체 QA 리포트 (2026-11-21)

범위: 엔진 규칙, 서버(방/재접속/타이머), 웹 UI(데스크톱 + 390px 모바일 폭), 운영(배포 환경).
방법: 코드 리뷰 → 결함 목록화 → 자동 테스트 추가 → 봇 클라이언트 + 브라우저로 시나리오 재현.

## 자동 테스트 (총 33개)

| 영역 | 내용 |
|---|---|
| 엔진 단위 | 공식 점수 예시(18점), 보너스 배수, 덱 크기, 차례/단계 강제, 방금 버린 카드 재획득 금지, 오름차순·투자 규칙, 매 판 첫 차례 무작위(자리별 고르게), 손패 비공개 뷰 |
| 엔진 퍼즈 | 9개 설정(프리셋 전부 + 2색 최소/투자 0장·같은 수/재획득 허용) × 15 시드 = 135 매치를 불법 수가 섞인 무작위 행동으로 끝까지 진행. 매 행동마다 **카드 보존(총 장수·중복 없음)**, **탐험대 순서 불변식**, **정상 종료/판 수** 검사 |
| 서버 | 암호/토큰 재접속, 인원 초과 시 관전, 방장 권한·승계, 카드 부족 설정 거부, 3인 매치 끝까지, 남의 차례/관전자/잘못된 요청 거부, 방 개수 제한 + 1시간 유휴 해제, 끊긴 플레이어 대신 진행, 방 단위 암호 시도 제한, 다음 판 중복 요청, 턴 타이머 |

## 발견 → 수정

| # | 심각도 | 문제 | 수정 |
|---|---|---|---|
| 1 | 높음 | 차례인 사람이 끊긴 채 안 돌아오면(타이머 없는 방) 게임이 영원히 멈춤 | 20초 이상 끊겨 있으면 다른 플레이어가 **"대신 진행"**(자동 버리기 + 덱에서 뽑기). 보드에 "연결 끊김" 표시 |
| 2 | 중간 | 턴 타이머를 서버 절대 시각으로 보내 기기 시계가 틀리면 남은 시간이 엉뚱함 | 서버가 **남은 ms**를 보내고 클라이언트가 수신 시점 기준으로 계산 |
| 3 | 낮음 | 새 턴 직후 타이머가 1초 더 크게 보임(91/90초) | 카운트다운을 렌더 시점 현재 시각으로 계산 |
| 4 | 중간 | 서버 재배포 후 재연결 실패 시 화면이 옛 상태로 멈춤 | 재접속 실패하면 안내와 함께 처음 화면으로 |
| 5 | 낮음 | 두 명이 동시에 "다음 판"을 누르면 한 명에게 오류 토스트 | 클라이언트가 본 판 번호/상태를 함께 보내고, 이미 진행됐으면 조용히 무시 |
| 6 | 중간 | 암호 시도 제한이 소켓 단위라 재접속으로 우회 가능 | 방 단위로 5분에 10회 제한 추가 |
| 7 | 낮음 | 버림 더미가 크면(20장+) 펼쳤을 때 화면 밖으로 넘침 | 펼침 높이를 최대 240px로 제한(장수에 따라 간격 축소) |
| 8 | UX | 차례·할 일이 작은 글씨로만 표시되어 인지가 어려움 | 상단 **차례 배너**(내 차례 강조·①내려놓기 ②가져오기 단계·남은 시간·덱 부족 경고), 내 차례 시작 시 진동 + 다른 탭이면 탭 제목 알림 |
| 9 | UX | 안 되는 행동을 해도 아무 반응이 없음 | 상황별 안내 + 배너 흔들림: "지금은 OO 님의 차례예요", "먼저 카드를 1장 가져오세요", "먼저 카드를 1장 내려놓으세요", "방금 버린 카드는 바로 다시 가져올 수 없어요", "이 탐험대에는 7보다 큰 숫자만…", "투자 카드는 숫자 카드를 놓기 전에만…", "같은 색 탐험대/버림 더미에만…" |
| 10 | 운영 | 빈 방이 30분 뒤 해제, 꽉 차면 2분 만에 회수 | 요청대로 **모두 나간 뒤 1시간 유휴면 해제**(`ROOM_IDLE_MINUTES`, 기본 60), 1분마다 + 방 생성 시 정리 |

## 후속 반영 (같은 날)

| 요청 | 반영 |
|---|---|
| 방장 방 닫기 | 로비·게임 화면에 방장 전용 "방 닫기"(두 번 눌러 확인). 모두에게 "방장이 방을 닫았어요" 안내 후 처음 화면으로, 방 즉시 해제 |
| 로비로 돌아가기를 각자 | 매치 종료 후 각자 "로비로 돌아가기" → 대기 로비. 아직 결과를 보는 사람은 "결과 보는 중", 돌아온 사람은 "대기 중" 표시. 모두 돌아오면 끝난 매치 정리. 방장은 대기 로비에서 설정 변경 가능, 기다리지 않고 시작도 가능(결과 보던 사람도 새 게임에 합류) |

## 확인했지만 그대로 둔 것 (알려진 제한)

- **재배포 시 진행 중 게임 소실**: 방 상태가 메모리에만 있음(단일 파드). 필요해지면 Redis 등에 스냅샷 저장.
- **방 5개가 1시간 유휴 방으로 꽉 차면** 새 방을 최대 1시간 못 만듦 — 1시간 보존 요구와 맞바꾼 것. 방장이 다 쓴 방은 **방 닫기**로 바로 해제 가능.
- **소켓 이벤트 속도 제한 없음**: 게임 이벤트는 서버가 모두 검증하므로 상태 오염은 없고, 공개 규모가 작아 보류.
- **실기기(iOS Safari/안드로이드 크롬) 테스트 미실시**: 데스크톱 크롬 + 390px 폭 iframe으로만 확인. 드래그(터치)와 진동은 실기기 확인 필요.
